использовать современный flat config.

Не создавать legacy .eslintrc для нового проекта без причины.

========================================
CODEX GLOBAL AWARENESS
======================

Я хочу, чтобы будущие Codex sessions знали о DevToolkit.

Сначала проверь, как ТЕКУЩАЯ установленная версия Codex загружает user-level global instructions.

Если она поддерживает:

%USERPROFILE%.codex\AGENTS.md

используй официальный текущий mechanism.

НЕ ПЕРЕЗАПИСЫВАЙ существующий AGENTS.md.

Сначала прочитай его.

Затем аккуратно добавь небольшой раздел, только если это безопасно.

Пример смысла:

# Local development environment

This machine has a reusable development toolkit at:
%USERPROFILE%\DevToolkit

Before installing new global development software:

* inspect existing tools;
* run dev-doctor / dev-versions when useful;
* prefer existing installed SDKs;
* prefer project-local dependencies;
* use pnpm for new JS/TS projects unless the project specifies another package manager;
* use uv for new Python projects;
* do not install editor plugins, MCP servers, frameworks or global npm packages without a clear need;
* consult %USERPROFILE%\DevToolkit\TOOLKIT.md for available tooling.

Этот GLOBAL AGENTS.md должен быть КОРОТКИМ.

НЕ вставляй туда весь этот огромный prompt.

Не засоряй context будущих чатов.

Если установленная версия Codex НЕ поддерживает этот механизм или работает с ним нестабильно:

НЕ придумывай решение.

Просто укажи это в отчёте.

========================================
DON'T BREAK WINDOWS
===================

НЕ:

disable Defender
disable SmartScreen
disable Firewall
disable UAC
set global ExecutionPolicy Unrestricted
disable security services
edit registry security policies
remove Windows components
modify boot config

Для единичного trusted PowerShell installer допускается process-scoped bypass, если это официальный installation path.

========================================
DON'T BREAK PATH
================

PATH:

* preserve current values
* deduplicate entries
* use user PATH where possible
* don't erase existing entries

Проверять executable resolution:

Get-Command

where.exe

После PATH изменения открыть новую shell для проверки.

========================================
DON'T BREAK PROJECTS
====================

НИКОГДА массово не менять существующие projects.

Эта настройка касается WORKSTATION, а не миграции моих репозиториев.

правильные on-demand project dependencies

чем:

300 global npm packages

prefer fewer

prefer official
prefer stable

prefer simple architecture until complexity is justified.
